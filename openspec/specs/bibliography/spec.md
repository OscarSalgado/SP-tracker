# Bibliography Specification

> Generated by openlore v1.0.0 on 2026-08-06 07:33

## Purpose

Aggregates per-article metadata from the articles directory into a consolidated BibTeX-style
references.bib file, enforcing required bibliographic fields.

## Requirements

> `scripts\generate_bibliography.py`

## Sub-components

> `BibliographyGenerator` is an orchestrator. Each sub-component below implements one logical block.

### Sub-component: BuildEntry

> Implements: `build_entry`

Formats a single article's metadata dictionary into a BibTeX entry string keyed by its slug.

#### Requirement: FormatBibtexEntry

The system SHALL the function shall construct a bibtex entry string from a slug and metadata dict, selecting the venue field name based on entry type and using metadata.get to retrieve field values.

#### Scenario: ValidMetadataProducesCompleteEntry
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** a slug and a metadata dict containing all required bibliographic fields (title, author, year, entry
type)
- **WHEN** build_entry is called
- **THEN** it SHALL return a well-formed BibTeX entry string with the slug as the citation key and all fields
rendered as lines

#### Scenario: VenueFieldResolvedByEntryType
- **GIVEN** metadata with an entry type present in VENUE_FIELD_BY_ENTRY_TYPE
- **WHEN** build_entry constructs the entry
- **THEN** it SHALL use VENUE_FIELD_BY_ENTRY_TYPE.get to determine the correct venue field name (e.g. journal
vs booktitle) for that entry type

#### Scenario: MissingRequiredField
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** metadata missing a required bibliographic field
- **WHEN** build_entry is called via the internal _field helper
- **THEN** it SHALL raise or signal an error indicating the required field is missing, rather than silently
omitting it
